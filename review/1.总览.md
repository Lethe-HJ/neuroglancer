# Neuroglancer 架构总览

本文档概述了 Neuroglancer 的主要类/模块，按子系统分组，每项包含职责、关键方法/字段和主要文件路径。

---

## A. 基础与通信 / 共享对象层

### RPC / SharedObject / registerSharedObjectOwner / registerRPC

- **职责**：前端主线程与 worker（chunk worker）之间的消息同步、共享对象注册与远程方法调用。
- **关键点**：SharedObject 子类可以在主线程注册为"所有者"，并在 worker 端建立对应的 counterpart；RPC 封装消息、promises 与回调。
- **主要文件**：
  - `src/worker_rpc.js` 及其 TS/JS 的引入位置（在 chunk 管理、layer 等处被使用）

### SharedWatchableValue / WatchableVisibilityPriority / TrackableValue / TrackableBoolean / NullarySignal

- **职责**：可观察的值和优先级（用于 visibility、capacity、进度通知等）。
- **关键字段/方法**：`value`、`changed` 信号、`watch`/`unwatch`。
- **主要文件**：
  - `src/shared_watchable_value.ts`
  - `src/visibility_priority/frontend.ts`
  - `src/trackable_value.js` 等

---

## B. Chunk 管理（主干：数据块的生命周期、调度、缓存）

### Chunk (frontend.ts / backend.ts)

- **职责**：表示单个数据块（chunk），记录状态（ChunkState：`SYSTEM_MEMORY`/`GPU_MEMORY`/`COMPLETE`/`LOADING` 等）。
- **关键字段/方法（frontend）**：`state`、`source` (ChunkSource)、`copyToGPU()`、`freeGPUMemory()`。
- **关键字段/方法（backend）**：在 worker 内维护实际数据缓冲、加载逻辑与标记生成。
- **文件**：
  - `src/chunk_manager/frontend.ts`
  - `src/chunk_manager/backend.ts`

### ChunkSource / ChunkSourceBase / ChunkSourceParameters / WithParameters 工厂

- **职责**：定义如何定位与请求特定 chunk（不同数据源实现此接口/基类）。WithParameters 用于将参数带入 SharedObject/RPC 编码。
- **关键点**：`encodeOptions` / `initializeCounterpart` 影响在 worker/主线程之间传递的构造/配置。
- **文件**：
  - `src/chunk_manager/frontend.ts`
  - 相关 datasource 的 `frontend.ts`

### ChunkQueueManager (frontend.ts)

- **职责**：队列化、优先级调度和把请求发给 worker 端实际执行；是 SharedObject（因此与 worker 存在 counterpart）。
- **关键字段**：`rpc`（RPC 实例）、capacity specifications、`registerDisposer` 等。
- **文件**：`src/chunk_manager/frontend.ts`

### ChunkManager (frontend.ts / backend.ts)

- **职责**：全局管理 chunk 的集合、缓存配置（CapacitySpecification）、分配/回收策略、chunk statistics。前端作为控制/视图方，后端做实际调度/加载。
- **关键字段**：capacity specs、统计数据结构（ChunkStatistics）等。
- **文件**：
  - `src/chunk_manager/frontend.ts`
  - `src/chunk_manager/backend.ts`

### CapacitySpecification / FrameNumberCounter

- **职责**：控制 GPU/system/download/compute 等各种资源限制；FrameNumberCounter 用于帧变化通知（驱动渲染/缓存更新）。
- **文件**：
  - `src/chunk_manager/frontend.ts`
  - `src/data_management_context.ts`

---

## C. 渲染视图（Slice / Perspective / RenderLayer）

### SliceViewBase / FrontendSliceViewBase

- **职责**：2D 切片视图管理，包含一组 VisibleLayer、相机/坐标变换、视图更新循环。
- **关键点**：与 SliceViewChunkSource/RenderLayer 交互以获取并渲染 chunks。
- **文件**：`src/sliceview/frontend.ts`

### SliceViewRenderLayer / PerspectiveViewRenderLayer / RenderLayer（renderlayer.js）

- **职责**：渲染图层抽象，把 chunk 数据（纹理 / 网格）转为 GPU 渲染调用。负责坐标变换、LOD 选择、着色器绑定等（具体子类实现）。
- **关键方法**：`render(context)`、`initialize`、`dispose`、`updateTransform` 等（各实现可能不同）。
- **文件**：
  - `src/renderlayer.js`（或 `.ts`）
  - `src/perspective_view/*`
  - `src/sliceview/*`

### PerspectivePanel / PerspectiveViewRenderContext

- **职责**：3D 透视面板容器，管理摄像机和渲染上下文。
- **文件**：
  - `src/perspective_view/panel.ts`
  - `src/perspective_view/render_layer.ts`

---

## D. DataManagementContext / Viewer / UI / Prefetch

### DataManagementContext

- **职责**：把 GL 上下文、Worker、ChunkQueueManager、ChunkManager 集成起来，负责 worker 的创建与生命周期管理。是渲染/数据管理的入口。
- **关键字段**：`worker`、`chunkQueueManager`、`chunkManager`、`rpc`（来自 chunkQueueManager）。
- **文件**：`src/data_management_context.ts`

### Viewer / ViewerUIConfiguration / Viewer.state（state restore/serialize）

- **职责**：顶层 UI，管理多视图、多层级、交互、URL/state 同步。构造 SliceView/PerspectivePanel、层面板与控件。
- **文件**：
  - `src/viewer.ts`
  - `src/main_python.ts`（Python 集成入口）

### PrefetchManager

- **职责**：基于指定的 state 列表创建"隐藏" Viewer，用于提前加载数据（优先级控制）。与 DataManagementContext 与 VisibilityPriority 协作。
- **文件**：`src/python_integration/prefetch.ts`

---

## E. 数据源（datasource：把各种后端协议映射为 ChunkSource）

### VolumeChunkSource / MultiscaleVolumeChunkSource / VolumeChunkSourceOptions

- **职责**：体积数据的 chunk 提供者（支持多尺度、不同数据类型、channels）。解析后端 metadata 并生成 chunk 请求。
- **文件**：
  - `src/sliceview/volume/frontend.ts`
  - `src/datasource/dvid/frontend.ts`
  - 其他 datasource 前端文件

### TileChunkSource / TileChunkSourceBase / TileChunkSourceParameters

- **职责**：瓦片/切片 API 的实现（通常用于 2D 图像服务）。
- **文件**：`src/datasource/render/frontend.ts`

### MeshSource / MultiscaleMeshSource / EncodedMeshData

- **职责**：提供网格（mesh）chunk；可能有多尺度或分片格式（EncodedMeshData、MultiscaleFragment 等）。
- **文件**：
  - `src/mesh/frontend.ts`
  - `src/mesh/backend.ts`

### 各种 datasource 具体实现（dvid、render、graphene、python）

- **职责**：实现与特定后端协议的交互、query 参数解析、数据类型映射（例如 dvid 的 stats、stackBounds、channels 等解析函数出现在 datasource/render/frontend.ts）。
- **文件举例**：
  - `src/datasource/dvid/frontend.ts`
  - `src/datasource/render/frontend.ts`
  - `src/datasource/graphene/frontend.ts`
  - `src/datasource/python/frontend.ts`

---

## F. Segmentation / Mesh / Skeleton（语义层）

### SegmentationDisplayState / SegmentationLayerSharedObject / SegmentWidgetFactory

- **职责**：维护 segmentation 的显示状态（哪些 segments 可见、颜色、分组选项、LOD 设置等），并向渲染层提供要渲染的 segment 列表。
- **关系**：Segmentation 层通常通过 MeshSource 请求网格或通过 label texture 在切片中渲染。
- **文件**：
  - `src/segmentation_display_state/frontend.ts`
  - `src/layer/segmentation/*`

### MeshLayer / MultiscaleMeshLayer / SingleMeshLayer

- **职责**：处理网格的 LOD、合并、缓冲区上传、着色与绘制。SingleMeshLayer 处理单一网格对象场景（例如单目标加载）。
- **关键字段/方法**：`requestFragments`、`decodeVertexPositionsAndIndices`（也有 backend 解码函数）、`updateBuffers`、`draw`。
- **文件**：
  - `src/mesh/frontend.ts`
  - `src/single_mesh/frontend.ts`
  - `src/mesh/backend.ts`

### SkeletonLayer / Skeleton backend

- **职责**：显示点-边（graph）结构（骨架），例如对分割对象的骨架化结果进行渲染。与 chunk/mesh 系统类似但数据格式不同。
- **文件**：
  - `src/skeleton/frontend.ts`
  - `src/skeleton/backend.ts`

---

## G. Worker 内实现（运行在 chunk worker / backend）

> **注意**：这些文件以 `backend.ts` 结尾，通常是在 worker 里运行的实现。

### chunk_manager/backend.ts

- **职责**：在 worker 内实际维护 chunk 对象、执行网络请求（或代理请求）、内存回收、优先级决策。提供 `withChunkManager` 工具以简化调用者（例如 sliceview/backend）访问。
- **关键点**：Chunk 在此拥有真实数据 buffer；`getNextMarkGeneration`、`withChunkManager`、`ChunkConstructor`、`ChunkRenderLayerBackend` 等是常见接口。

### sliceview/backend.ts、mesh/backend.ts、skeleton/backend.ts

- **职责**：在 worker 内进行数据解码、网格/骨架解码或切片处理（例如解析 EncodedMeshData 到顶点/索引缓冲、gzip/压缩解码、label->vertex 处理等）。这些实现把处理完成的数据送回主线程（或通过 SharedObject 通知）。
- **关键函数**：`decodeVertexPositionsAndIndices`（mesh/backend.ts 中），以及 chunk 的 fill/load 逻辑。

## H. 其它工具/辅助模块

### util/*

- **职责**：跨模块的通用功能，被所有上层类广泛使用。

## 主要类/模块之间的高层关系与数据流

### 1. 高层次顺序（渲染一次帧时的主要路径）

```
Viewer (UI)
  → 创建/配置 Views (SliceView / PerspectivePanel)
    → 每个 VisibleLayer 建立相应的 RenderLayer / LayerState
      → Layer 使用 datasource 构造对应的 ChunkSource (VolumeChunkSource / MeshSource / TileChunkSource)
        → RenderLayer 请求 chunk：chunkRequest → ChunkManager (frontend)
          → ChunkManager 将请求交给 ChunkQueueManager（SharedObject）
            → ChunkQueueManager 通过 RPC 发送到 worker（chunk_worker）
              → worker 的 chunk_manager/backend 收到请求，使用具体 backend（sliceview/backend、mesh/backend、skeleton/backend）去加载/解码数据（可能进行网络请求或本地解码）
                → worker 更新 Chunk 状态 → 通过 RPC/SharedObject 更新主线程的 Chunk 对象状态与数据指针/共享视图
                  → 主线程 SliceView/RenderLayer 收到数据后，将数据上传至 GPU（copyToGPU 或创建纹理/缓冲区）并绘制
```

### 2. ASCII 形式的简短关系图

```
Viewer/UI
  ├─ View (SliceView / PerspectivePanel)
  │    └─ RenderLayer (VolumeLayer / SegmentationLayer / MeshLayer / SkeletonLayer)
  │         └─ ChunkSource (VolumeChunkSource / MeshSource / TileChunkSource)
  │              └─ ChunkManager (frontend) → ChunkQueueManager (SharedObject) → RPC → chunk_worker
  │                   └─ backend implementations (chunk_manager/backend.ts + sliceview/backend.ts / mesh/backend.ts / skeleton/backend.ts)
  │                        └─ 后端数据加载/解码（HTTP/其他） → 更新 Chunk → 回传主线程 → GPU 上传 → 渲染
  └─ UI 控件 / SegmentationDisplayState / Viewer.state / PrefetchManager（影响优先级与可见性）
```

## 关键交互点/关注点（调试与扩展）

- **SharedObject/RPC 边界**：理解哪些对象是仅在主线程（frontend.ts）维护，哪些在 worker（backend.ts）拥有"counterpart"，这对调试同步问题非常重要。
- **Chunk 状态机（ChunkState）**：是调度与释放策略的核心（`SYSTEM_MEMORY` / `GPU_MEMORY` / `LOADING` / `COMPLETE` 等）。
- **CapacitySpecification**：控制内存/下载/compute 限额，调整会显著影响性能。
- **数据源 metadata 解析（datasource/*/frontend.ts）**：影响坐标、voxel bounds、channels、分辨率等，是正确定位 chunk 的基础。
- **Mesh 解码（mesh/backend.ts 与 mesh/frontend.ts 的配合）**：网格格式解码常常是复杂与性能敏感点。
- **Prefetch / VisibilityPriority**：预取策略会改变网络请求模式，调测加载顺序时要注意这一层。

1. `src/data_management_context.ts`（理解 worker 的创建与 Chunk 管理入口）
2. `src/chunk_manager/frontend.ts`（Chunk、ChunkSource、QueueManager、ChunkManager 的 frontend 概念）
3. `src/worker_rpc.js`（理解 SharedObject/RPC 机制）
4. `src/chunk_manager/backend.ts`（worker 内 chunk 生命周期与调度实现）
5. `src/sliceview/frontend.ts` + `src/sliceview/backend.ts`（切片视图的前/后端配合）
6. `src/mesh/frontend.ts` + `src/mesh/backend.ts` + `src/single_mesh/frontend.ts`（网格请求/解码/渲染）
7. `src/datasource/*/frontend.ts`（各后端协议如何被解析并映射为 ChunkSource）
8. `src/viewer.ts`、`src/perspective_view/*`、`src/layer/segmentation/*`（UI 层与显示态）
