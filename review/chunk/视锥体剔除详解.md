2. **对每个chunk进行视锥体相交测试**
3. **根据距离和重要性选择合适的LOD级别**

### 3. **视锥体剔除的具体流程**

```typescript
// 伪代码展示视锥体剔除的逻辑
function getMultiscaleChunksToDraw(
  manifest: ChunkManifest,
  mvpMatrix: mat4,
  clippingPlanes: Plane[],
  detailCutoff: number,
  screenWidth: number,
  screenHeight: number,
  chunkCallback: (lod: number, chunkIndex: number) => boolean,
  lodCallback: () => void
) {
  // 注意：实际实现是递归的，从粗到细逐级细分
  // 这里展示的是简化的伪代码逻辑
  
  function handleChunk(lod: number, chunk: ChunkInfo, priorLodScale: number) {
    // 1. 计算chunk的AABB（轴对齐包围盒）
    const aabb = calculateChunkAABB(chunk);
    
    // 2. 视锥体相交测试
    if (frustumAABBIntersection(aabb, clippingPlanes)) {
      // 3. 计算屏幕投影大小（像素尺寸）
      const pixelSize = calculatePixelSize(aabb, mvpMatrix, screenWidth, screenHeight);
      
      // 4. LOD选择的关键判断
      if (priorLodScale === 0 || pixelSize * detailCutoff < priorLodScale) {
        const lodScale = lodScales[lod];
        
        // 5. 如果当前LOD有数据，则使用它
        if (lodScale !== 0) {
          callback(lod, chunk, lodScale / pixelSize); // 使用当前LOD
        }
        
        // 6. 决定是否需要更精细的LOD
        if (lod > 0 && (lodScale === 0 || pixelSize * detailCutoff < lodScale)) {
          // 需要更精细的LOD，递归处理子chunk
          for (const childChunk of chunk.children) {
            handleChunk(lod - 1, childChunk, lodScale === 0 ? priorLodScale : lodScale);
          }
        }
      }
    }
  }
  
  // 从最粗的LOD开始递归
  handleChunk(maxLod, rootChunk, 0);
}
```

#### **重要结论：混合渲染策略**

1. **粗糙LOD作为基础**：首先渲染粗糙的LOD作为基础覆盖
2. **精细LOD作为补充**：在需要的区域叠加更精细的LOD
3. **分层渲染**：不同精度的chunk可以同时存在并渲染

#### **为什么需要保留粗糙LOD？**

1. **填补空隙**：精细chunk可能还在加载中，粗糙chunk提供即时覆盖
2. **减少闪烁**：避免chunk加载时的空白区域
3. **渐进式细化**：提供从粗糙到精细的平滑过渡
4. **内存管理**：精细chunk可能因内存限制被卸载，粗糙chunk作为后备

物体在屏幕上显示得越大，就需要越精细的细节；但粗糙的细节仍然作为基础保留。

### 4. **视锥体裁剪平面的构建**

#### **4.1 视锥体的6个裁剪平面**

视锥体由6个平面组成，每个平面都指向视锥体内部：

```typescript
interface Plane {
  normal: vec3;    // 平面法向量（指向视锥体内部）
  distance: number; // 平面到原点的距离
}

function extractFrustumPlanes(mvpMatrix: mat4): Plane[] {
  const planes: Plane[] = [];
  
  // 从MVP矩阵中提取6个裁剪平面
  // 注意：法向量都指向视锥体内部
  
  // 左平面: mvp[3] + mvp[0]
  planes[0] = normalizePlane([
    mvpMatrix[3] + mvpMatrix[0],   // normal.x
    mvpMatrix[7] + mvpMatrix[4],   // normal.y  
    mvpMatrix[11] + mvpMatrix[8],  // normal.z
    mvpMatrix[15] + mvpMatrix[12]  // distance
  ]);
  
  // 右平面: mvp[3] - mvp[0]
  planes[1] = normalizePlane([
    mvpMatrix[3] - mvpMatrix[0],
    mvpMatrix[7] - mvpMatrix[4],
    mvpMatrix[11] - mvpMatrix[8],
    mvpMatrix[15] - mvpMatrix[12]
  ]);
  
  // 底平面: mvp[3] + mvp[1]
  planes[2] = normalizePlane([
    mvpMatrix[3] + mvpMatrix[1],
    mvpMatrix[7] + mvpMatrix[5],
    mvpMatrix[11] + mvpMatrix[9],
    mvpMatrix[15] + mvpMatrix[13]
  ]);
  
  // 顶平面: mvp[3] - mvp[1]
  planes[3] = normalizePlane([
    mvpMatrix[3] - mvpMatrix[1],
    mvpMatrix[7] - mvpMatrix[5],
    mvpMatrix[11] - mvpMatrix[9],
    mvpMatrix[15] - mvpMatrix[13]
  ]);
  
  // 近平面: mvp[3] + mvp[2]
  planes[4] = normalizePlane([
    mvpMatrix[3] + mvpMatrix[2],
    mvpMatrix[7] + mvpMatrix[6],
    mvpMatrix[11] + mvpMatrix[10],
    mvpMatrix[15] + mvpMatrix[14]
  ]);
  
  // 远平面: mvp[3] - mvp[2]
  planes[5] = normalizePlane([
    mvpMatrix[3] - mvpMatrix[2],
    mvpMatrix[7] - mvpMatrix[6],
    mvpMatrix[11] - mvpMatrix[10],
    mvpMatrix[15] - mvpMatrix[14]
  ]);
  
  return planes;
}

function normalizePlane(plane: number[]): Plane {
  const length = Math.sqrt(plane[0] * plane[0] + plane[1] * plane[1] + plane[2] * plane[2]);
  return {
    normal: [plane[0] / length, plane[1] / length, plane[2] / length],
    distance: plane[3] / length
  };
}
```

#### **4.2 平面法向量方向与距离的关系**

**关键概念：平面方程 `ax + by + cz + d = 0`**

- **法向量 `(a, b, c)`**：垂直于平面，指向平面的"正侧"
- **距离参数 `d`**：原点到平面的**有符号距离** × (-1)

```typescript
// 平面方程的几何意义
function pointToPlaneDistance(point: vec3, plane: Plane): number {
  // 点到平面的有符号距离
  const distance = dot(plane.normal, point) + plane.distance;
  // 点积的几何意义是 A · B = |A|*|B|*cosθ 其中θ为向量A和向量B的夹角
  // 上面式子中 |B|*cosθ 为向量B在向量A方向上的投影 而|A|为1(因为是法向量)
  // 因此 dot(plane.normal, point) 即为point表示的向量在平面法向量上的投影

  // 距离的符号含义：
  // distance > 0: 点在平面的正侧（法向量指向的一侧）
  // distance = 0: 点在平面上
  // distance < 0: 点在平面的负侧（法向量背向的一侧）
  
  return distance;
}
```



### 5. **AABB与视锥体相交测试算法**

```typescript
function frustumAABBIntersection(aabb: AABB, clippingPlanes: Plane[]): boolean {
  // 对每个裁剪平面进行测试
  for (const plane of clippingPlanes) {
    // 计算AABB的正向顶点（距离平面最远的顶点）
    // 由于法向量指向视锥体内部，正向顶点是最有可能在视锥体内的顶点
    const positiveVertex = [
      plane.normal[0] > 0 ? aabb.max[0] : aabb.min[0],
      plane.normal[1] > 0 ? aabb.max[1] : aabb.min[1],
      plane.normal[2] > 0 ? aabb.max[2] : aabb.min[2]
    ];
    
    // 计算正向顶点到平面的距离
    const distance = dot(plane.normal, positiveVertex) + plane.distance;
    
    // 如果连最有可能在视锥体内的顶点都在平面外侧，则整个AABB都在视锥体外
    if (distance < 0) {
      return false; // 不相交，可以剔除
    }
  }
  return true; // 相交或包含，需要渲染
}
```

#### **5.1 算法的数学原理**

```typescript
// 为什么选择"正向顶点"？
function explainPositiveVertex(plane: Plane, aabb: AABB) {
  // 对于法向量 normal = (nx, ny, nz)
  // AABB的8个顶点中，哪个顶点在法向量方向上最远？
  
  const vertices = [
    [aabb.min[0], aabb.min[1], aabb.min[2]], // (min, min, min)
    [aabb.min[0], aabb.min[1], aabb.max[2]], // (min, min, max)
    [aabb.min[0], aabb.max[1], aabb.min[2]], // (min, max, min)
    [aabb.min[0], aabb.max[1], aabb.max[2]], // (min, max, max)
    [aabb.max[0], aabb.min[1], aabb.min[2]], // (max, min, min)
    [aabb.max[0], aabb.min[1], aabb.max[2]], // (max, min, max)
    [aabb.max[0], aabb.max[1], aabb.min[2]], // (max, max, min)
    [aabb.max[0], aabb.max[1], aabb.max[2]]  // (max, max, max)
  ];
  
  // 正向顶点就是让 dot(normal, vertex) 最大的顶点
  // 这等价于：
  const positiveVertex = [
    plane.normal[0] > 0 ? aabb.max[0] : aabb.min[0], // 选择让nx*x最大的x
    plane.normal[1] > 0 ? aabb.max[1] : aabb.min[1], // 选择让ny*y最大的y  
    plane.normal[2] > 0 ? aabb.max[2] : aabb.min[2]  // 选择让nz*z最大的z
  ];
  
  return positiveVertex;
}
```

```typescript
function cullLogic(aabb: AABB, plane: Plane) {
  const positiveVertex = getPositiveVertex(aabb, plane);
  const distance = dot(plane.normal, positiveVertex) + plane.distance;
  
  if (distance < 0) {
    // 连最靠近视锥体内部的顶点都在平面外侧
    // 说明整个AABB都在视锥体外，可以安全剔除
    return "CULL";
  } else {
    // 至少有部分AABB在视锥体内，不能剔除
    // 注意：这里可能是完全包含，也可能是部分相交
    return "KEEP";
  }
}
```

## 疑问1：使用AABB与视锥体相交测试

### AABB（Axis-Aligned Bounding Box）与视锥体相交测试原理

**AABB定义：**

```typescript
interface AABB {
  xLower: number;
  yLower: number;
  zLower: number; // 最小点
  xUpper: number;
  yUpper: number;
  zUpper: number; // 最大点
}
```

**视锥体表示：**
视锥体由6个平面组成（左、右、上、下、近、远），每个平面用方程 `ax + by + cz + d = 0` 表示。

**相交测试算法：**

```typescript
function isAABBVisible(
  xLower: number,
  yLower: number,
  zLower: number,
  xUpper: number,
  yUpper: number,
  zUpper: number,
  clippingPlanes: Float32Array,
): boolean {
  // clippingPlanes包含6个平面，每个平面4个系数[a,b,c,d]
  for (let i = 0; i < 6; i++) {
    const planeOffset = i * 4;
    const a = clippingPlanes[planeOffset];
    const b = clippingPlanes[planeOffset + 1];
    const c = clippingPlanes[planeOffset + 2];
    const d = clippingPlanes[planeOffset + 3];

    // 计算AABB的8个顶点中在法向量方向上的投影最大的点（ positive vertex ）
    const px = a > 0 ? xUpper : xLower;
    const py = b > 0 ? yUpper : yLower;
    const pz = c > 0 ? zUpper : zLower;

    // 如果positive vertex都在平面外侧，则整个AABB在视锥体外
    if (a * px + b * py + c * pz + d < 0) {
      return false; // AABB完全在视锥体外
    }
  }
  return true; // AABB与视锥体相交或包含在内
}
```

每个平面用方程表示: ax + by + cz + d = 0
其中 (a,b,c) 是平面法向量，d是距离参数

### 关键算法 - Positive Vertex测试：

对于给定平面，AABB的8个顶点中**在法向量方向上的投影最大**的那个顶点。

```text
平面方程: ax + by + cz + d = 0
法向量: n = (a, b, c)
p1 p2点为在相应平面法向量方向上的投影最大的点（ positive vertex ）

             近平面
                |
                │
                │─────>n1      远平面
                │                │     ●────────●
                │                │     │        │
  ●────────●    │         n2<────│     │        │
  │        │    │                │     ●────────●
  │        │    │                      p2
  ●────────●    │
           p1   │
```

Positive Vertex的选择规则：

```typescript
const px = a > 0 ? xUpper : xLower; // 如果法向量x分量>0，选择x最大值，否则选x最小值
const py = b > 0 ? yUpper : yLower; // 如果法向量y分量>0，选择y最大值，否则选y最小值
const pz = c > 0 ? zUpper : zLower; // 如果法向量z分量>0，选择z最大值，否则选z最小值
```

距离计算和可见性判断

```typescript
// 计算positive vertex到平面的距离
if (a * px + b * py + c * pz + d < 0) {
  return false; // AABB完全在视锥体外
}
```

上面代码用到的结论 `n.p + d < 0` 则 该点p位于平面的反面(正面为法向量正方向的那一面)
n.p 表示 向量p在法向量n上的投影 该投影 + d < 0 则说明该点在平面反面
其中 n.p 即为 a * px + b * py + c * pz

### 问题：精细LOD与粗糙LOD的共存关系

基于对源码的深入分析，我们发现neuroglancer采用了一种**分层混合渲染**的策略，而不是简单的LOD替换。

### 源码分析：递归细分的实现逻辑

```typescript
  // 第2层：LOD 1 (中等精度层)
  midLayer: {
    lod: 1,
    chunks: ["region_A_1_lod1", "region_A_2_lod1", "region_B_1_lod1"],
    purpose: "在重要区域提供中等精度细节"
  },
  
  // 第3层：LOD 0 (最精细层)
  detailLayer: {
    lod: 0,
    chunks: ["region_A_1_1_lod0", "region_A_1_2_lod0"],
    purpose: "在焦点区域提供最高精度细节"
  }

```

#### **1. 渐进式加载**

### 视觉效果对比

#### **传统LOD替换方式**
```
距离近：只显示LOD 0 ❌ 可能有空洞
距离中：只显示LOD 1 ❌ 可能有空洞  
距离远：只显示LOD 2 ✅ 正常显示
```

#### **Neuroglancer分层方式**
```
距离近：LOD 2 + LOD 1 + LOD 0 ✅ 无空洞，最佳质量
距离中：LOD 2 + LOD 1 ✅ 无空洞，良好质量
距离远：LOD 2 ✅ 无空洞，基础质量
```

### 性能影响分析

#### **优势**
- **无渲染空洞**：始终有基础覆盖
- **平滑过渡**：从粗糙到精细的渐进效果
- **加载友好**：不依赖所有精细chunk都加载完成

#### **代价**
- **渲染开销**：需要渲染多个层次的chunk
- **内存使用**：同时保持多个LOD级别
- **复杂度**：渲染逻辑更加复杂

### 结论

**neuroglancer的LOD系统采用分层混合渲染，粗糙LOD不会被精细LOD完全替代，而是作为基础层继续存在。这种设计确保了：**

1. **视觉连续性**：没有渲染空洞
2. **加载性能**：渐进式质量提升
3. **内存弹性**：在内存压力下优雅降级
4. **用户体验**：始终有内容显示，避免等待空白

这就是为什么在使用更精细chunk的同时，粗糙的chunk仍然会被保留和使用的原因。
