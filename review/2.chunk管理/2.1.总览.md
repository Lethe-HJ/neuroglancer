# Chunk 管理总览

Chunk 管理系统是 Neuroglancer 的核心数据管理模块，负责数据块的**生命周期管理**、**优先级调度**、**网络下载**、**内存缓存**以及**CPU/GPU 内存传输**。所有数据操作都在 WebWorker 线程中异步执行，以保证主线程的响应性。

---

## 核心概念

### Chunk（数据块）

**Chunk** 是数据管理的基本单元，可以表示：
- `64³` 体素块（体积数据）
- 网格片段（mesh fragment）
- 网格清单（mesh manifest）
- 骨架线段（skeleton segment）

每个 Chunk 都有：
- **唯一标识**：`key`（字符串）
- **状态**：`ChunkState`（状态机）
- **优先级**：`priorityTier` + `priority`（层级 + 数值）
- **内存占用**：`systemMemoryBytes`、`gpuMemoryBytes`
- **所属源**：`source`（ChunkSource）

### ChunkState（状态机）

Chunk 的状态转换流程：

```
NEW → QUEUED → DOWNLOADING → SYSTEM_MEMORY_WORKER → SYSTEM_MEMORY → GPU_MEMORY
                                                          ↑              ↓
                                                          └──────────────┘
```

**状态说明**：
- **`NEW`**：刚创建，尚未进入队列
- **`QUEUED`**：等待下载，在优先级队列中
- **`DOWNLOADING`**：正在从网络下载
- **`SYSTEM_MEMORY_WORKER`**：在 Worker 线程的系统内存中（已下载但未传输到主线程）
- **`SYSTEM_MEMORY`**：在主线程的系统内存中
- **`GPU_MEMORY`**：已上传到 GPU 显存
- **`FAILED`**：下载失败
- **`EXPIRED`**：已过期，将被删除

### ChunkPriorityTier（优先级层级）

优先级分为三个层级（从高到低）：

1. **`VISIBLE`**：当前可见且渲染所需的数据
2. **`PREFETCH`**：预期即将可见的数据（预取）
3. **`RECENT`**：最近使用过但当前不需要的数据（LRU 缓存）

每个层级内还有数值优先级（`priority`），数值越大优先级越高。

## 核心组件

### 1. ChunkSource（数据源）

**职责**：定义如何定位和请求特定 chunk，是不同数据源（Volume、Mesh、Tile 等）的抽象接口。

**关键特性**：
- 继承自 `SharedObject`，在主线程和 Worker 线程都有对应实例
- 维护一个 `chunks` Map，存储该源的所有 chunk
- 通过 `getChunk()` 方法获取或创建 chunk
- 支持 `WithParameters` 工厂模式，用于参数化配置

**文件位置**：
- Frontend：`src/chunk_manager/frontend.ts`
- Backend：`src/chunk_manager/backend.ts`

### 2. ChunkManager（管理器）

**职责**：全局管理所有 ChunkSource 的集合，提供统一的 chunk 获取接口。

**关键功能**：
- **`getChunkSource()`**：工厂方法，根据配置获取或创建 ChunkSource（使用 memoize 缓存）
- 管理 ChunkSource 的生命周期
- 协调优先级更新（`recomputeChunkPriorities`）
- 统计信息收集（`layerChunkStatisticsUpdated`）

**架构特点**：
- Frontend 和 Backend 都是 `SharedObject`
- Frontend 作为控制/视图方，Backend 负责实际调度

**文件位置**：
- Frontend：`src/chunk_manager/frontend.ts`
- Backend：`src/chunk_manager/backend.ts`

### 3. ChunkQueueManager（队列管理器）

**职责**：队列化、优先级调度、资源管理和状态转换的核心调度器。

**关键功能**：
- **优先级队列管理**：维护多个优先级队列（VISIBLE、PREFETCH、RECENT）
- **资源容量控制**：管理 GPU 内存、系统内存、下载带宽、计算资源
- **状态转换调度**：控制 chunk 从 QUEUED → DOWNLOADING → SYSTEM_MEMORY → GPU_MEMORY
- **LRU 淘汰策略**：当资源不足时，淘汰低优先级的 chunk

**队列结构**：
- `queuedDownloadPromotionQueue`：等待下载的队列（按优先级）
- `downloadEvictionQueue`：正在下载的队列（用于取消低优先级下载）
- `systemMemoryEvictionQueue`：系统内存中的队列（LRU）
- `gpuMemoryPromotionQueue`：等待上传 GPU 的队列
- `gpuMemoryEvictionQueue`：GPU 内存中的队列（用于释放）

**文件位置**：
- Frontend：`src/chunk_manager/frontend.ts`
- Backend：`src/chunk_manager/backend.ts`

### 4. CapacitySpecification（容量规格）

**职责**：定义各种资源的限制（数量限制 + 大小限制）。

**资源类型**：
- **`gpuMemory`**：GPU 显存容量
- **`systemMemory`**：系统内存容量
- **`download`**：并发下载数量
- **`compute`**：并发计算任务数量

每个容量规格包含：
- `itemLimit`：项目数量限制
- `sizeLimit`：总大小限制（字节）

**文件位置**：`src/chunk_manager/frontend.ts`

## 数据流与生命周期

### 1. Chunk 请求流程

```
RenderLayer 请求 chunk
    ↓
ChunkSource.getChunk(key)
    ↓
ChunkManager.requestChunk(chunk, tier, priority)
    ↓
ChunkQueueManager 更新优先级
    ↓
ChunkQueueManager.process() 调度
    ↓
根据优先级和资源容量，决定：
  - 开始下载（QUEUED → DOWNLOADING）
  - 上传 GPU（SYSTEM_MEMORY → GPU_MEMORY）
  - 淘汰低优先级 chunk
```

### 2. 下载流程

```
QUEUED (在优先级队列中)
    ↓
检查下载容量 → 开始下载
    ↓
DOWNLOADING (调用 ChunkSource.download())
    ↓
网络请求完成 → 解码数据
    ↓
SYSTEM_MEMORY_WORKER (在 Worker 中)
    ↓
传输到主线程（如果需要）
    ↓
SYSTEM_MEMORY (在主线程中)
    ↓
检查 GPU 容量 → 上传 GPU
    ↓
GPU_MEMORY (可用于渲染)
```

### 3. 资源淘汰流程

当资源不足时（例如 GPU 内存已满）：

```
需要上传新 chunk 到 GPU
    ↓
检查 gpuMemoryCapacity.availableSize
    ↓
容量不足 → 从 gpuMemoryEvictionQueue 选择低优先级 chunk
    ↓
释放 GPU 内存（GPU_MEMORY → SYSTEM_MEMORY）
    ↓
为新 chunk 腾出空间
    ↓
上传新 chunk 到 GPU
```

## 前后端协作

### Frontend（主线程）

- **Chunk**：轻量级对象，只包含状态和引用
- **ChunkSource**：维护 chunk 的 Map，处理 chunk 请求的回调
- **ChunkManager**：提供 `getChunkSource()` 工厂方法
- **ChunkQueueManager**：接收来自 Worker 的状态更新，管理 GPU 上传

### Backend（Worker 线程）

- **Chunk**：包含实际数据 buffer，维护详细的状态和优先级
- **ChunkSource**：实现 `download()` 方法，执行网络请求和数据解码
- **ChunkManager**：管理优先级更新，协调各层的 chunk 请求
- **ChunkQueueManager**：执行实际的调度逻辑，管理所有优先级队列

### 通信机制

通过 **RPC（Remote Procedure Call）** 和 **SharedObject** 机制实现前后端通信：

- **`Chunk.update`**：Worker 通知 Frontend chunk 状态变化
- **`Chunk.retrieve`**：Frontend 从 Worker 获取 chunk 数据
- **SharedObject**：ChunkSource、ChunkManager、ChunkQueueManager 都是 SharedObject，在两端都有对应实例

## 关键设计模式

### 1. 工厂模式

`ChunkManager.getChunkSource()` 使用 memoize 缓存，相同配置返回同一个 ChunkSource 实例。

### 2. 策略模式

不同的 ChunkSource 实现不同的 `download()` 策略（HTTP、本地解码等）。

### 3. 观察者模式

- `chunkRequesters`：chunk 就绪时通知请求者
- `visibleChunksChanged`：可见 chunk 变化时通知
- `recomputeChunkPriorities`：优先级需要重新计算时通知

### 4. 状态机模式

Chunk 的状态转换由 `ChunkQueueManager.updateChunkState()` 统一管理，确保状态转换的一致性。

## 性能优化要点

1. **异步处理**：所有下载和解码都在 Worker 线程，不阻塞主线程
2. **优先级调度**：优先处理 VISIBLE chunk，保证渲染流畅
3. **资源限制**：通过 CapacitySpecification 防止内存溢出
4. **LRU 淘汰**：自动淘汰不常用的 chunk，释放资源
5. **批量更新**：chunk 状态更新可以批量处理，减少 RPC 调用
6. **对象复用**：ChunkSource 通过 memoize 复用，减少重复创建

## 总结

Chunk 管理系统通过**状态机**、**优先级队列**、**资源容量控制**和**前后端协作**，实现了高效的数据加载、缓存和渲染。核心思想是：

1. **按需加载**：只加载当前可见和即将可见的数据
2. **优先级驱动**：根据可见性和重要性调度资源
3. **资源受限**：在有限的 GPU/内存/带宽下，最大化渲染性能
4. **异步处理**：所有 I/O 和计算都在 Worker 线程，保证 UI 响应性
